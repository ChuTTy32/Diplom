# WireGuard Zero Trust VPN

> **Статус:** компонент **production multi-host** сценария. В демонстрационный `docker-compose.yml` сервис WireGuard **не включён** и не запускается — на одномашинном стенде сервисы общаются по изолированным Docker-сетям (`backend_net`, `frontend_net`). Этот каталог содержит подготовленные ключи, конфигурации и инструкции для развёртывания VPN при разнесении агента, backend и borg по разным хостам. Команды `docker exec wireguard ...` ниже предполагают, что сервис WireGuard предварительно добавлен в Compose-стек.

## Архитектура сети

```
┌─────────────────────────────────────────────────────┐
│                  VPN-сеть 10.0.0.0/24                │
│                                                       │
│  ┌──────────────┐    ┌──────────────┐                │
│  │   Agent      │    │   Borg       │                │
│  │  10.0.0.2    │    │  10.0.0.3    │                │
│  └──────┬───────┘    └──────┬───────┘                │
│         │  зашифрован       │  зашифрован             │
│         └─────────┬─────────┘                        │
│                   │                                   │
│          ┌────────▼────────┐                         │
│          │   WireGuard     │                         │
│          │   10.0.0.1      │                         │
│          │   (сервер)      │                         │
│          └────────┬────────┘                         │
│                   │                                   │
│          ┌────────▼────────┐                         │
│          │   Backend API   │                         │
│          │   172.20.0.x    │                         │
│          └─────────────────┘                         │
└─────────────────────────────────────────────────────┘
```

## Принцип Zero Trust

- Агент НЕ знает реальный IP backend — только VPN-адрес 10.0.0.1
- Borg НЕ знает реальный IP репозитория — трафик через туннель
- Весь трафик метрик и бэкапов зашифрован WireGuard (ChaCha20)
- Даже если злоумышленник перехватит пакеты — данные зашифрованы

## Развёртывание

### Шаг 1: Генерация ключей (один раз)
```bash
# Установить wireguard-tools на хосте
sudo apt install wireguard-tools

# Генерируем ключи
bash wireguard/scripts/gen_keys.sh
```

### Шаг 2: Скопировать конфиги в папки
```bash
# Сервер (wireguard контейнер)
cp wireguard/config/wg0-server.conf wireguard/config/wg0.conf

# Конфиги агента и борга монтируются автоматически
```

### Шаг 3: Запуск
```bash
docker compose up -d wireguard
docker compose up -d
```

### Шаг 4: Проверка туннеля
```bash
# Статус WireGuard
docker exec wireguard wg show

# Пинг агента через туннель
docker exec wireguard ping 10.0.0.2

# Пинг борга через туннель
docker exec wireguard ping 10.0.0.3
```

## Безопасность

| Свойство | Значение |
|----------|----------|
| Шифрование | ChaCha20-Poly1305 |
| Обмен ключами | Curve25519 |
| Хеширование | BLAKE2s |
| Аутентификация | Ed25519 |

## Важно

- Приватные ключи в `wireguard/config/*.key` — НЕ коммитить в git
- Добавить в `.gitignore`: `wireguard/config/*.key`
- В продакшне использовать Vault или Docker Secrets для хранения ключей
